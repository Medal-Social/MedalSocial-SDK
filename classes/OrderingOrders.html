    Class OrderingOrders

    A guest's orders: medal.ordering.orders. Call it server-side with the workspace API key — create and cancel need ordering.order.create, get and status need ordering.order.read. An order of another workspace, or an unknown id, is 404 ORDER_NOT_FOUND.

    create

    • create(
          input: OrderingCreateOrderInput,
          options: OrderingCreateOrderOptions,
      ): Promise<OrderCreatedEnvelope>

      Place an order. Resolves 201 the first time and 200 when the same key and body is sent again; both carry { order_id, order_number, status }.

      The idempotencyKey is required and goes out as Idempotency-Key on every attempt, so the SDK's automatic retry on 429/5xx replays instead of placing a second order. A business refusal is a 422 MedalApiError; narrow it with isOrderingRefusal to read code and details. Other failures: 404 ORDERING_LOCATION_NOT_FOUND, 409 IDEMPOTENCY_KEY_CONFLICT / IDEMPOTENCY_CONFLICT (same key, different body), 409 IDEMPOTENCY_IN_PROGRESS (wait and send again with the same key), 429 RATE_LIMITED.

      const { data } = await medal.ordering.orders.create(
        {
          location_id: "loc_1",
          channel: "takeaway",
          lines: [{ product_id: "p_1", quantity: 2, option_ids: ["o_1"] }],
          customer: { name: "Kari", phone: "+4791234567" },
          preferences: { cutlery: true },
          payment_method: "pay_at_counter",
        },
        { idempotencyKey: cart.idempotencyKey, clientIp: request.ip },
      );
